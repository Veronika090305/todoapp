Отчёт по практической работе. Разработка to-do приложения через TDD

Вариант 6. Веб-приложение для управления задачами (to-do list) на Flask.
Методология - TDD (Test-Driven Development) - разработка через тестирование.
Инструменты - Python 3, Flask, pytest.

1. Цель работы
Познакомиться с принципами автоматического и непрерывного тестирования на примере методологии TDD и разработать часть программного обеспечения (модуль управления задачами и веб-интерфейс к нему), выполнив 15 итераций цикла TDD.

2. Принцип TDD
В основе TDD лежит короткий повторяющийся цикл Red - Green - Refactor:
1. Red (красный) - сначала пишется тест на ещё не существующую функциональность. Тест запускается и закономерно падает (кода нет).
2. Green (зелёный) - пишется минимальный код, которого достаточно, чтобы тест прошёл (не более).
3. Refactor (рефакторинг) - код улучшается (убираются повторы, проясняются имена), при этом все тесты должны продолжать проходить.
Тесты пишутся по правилу «от простого к сложному»: сначала тривиальные случаи, затем всё более сложные. Одна итерация занимает несколько минут, поэтому тестовая база наполняется быстро. Главная идея - код всегда покрыт тестами, и любая регрессия сразу обнаруживается.

3. Архитектура решения
Приложение разделено на два слоя, что облегчает тестирование:
- Доменная модель (`models.py`) - класс `TaskManager` и структура `Task`. Это чистая логика без привязки к вебу: добавление, поиск, выполнение, удаление задач. Тестируется напрямую, тесты очень быстрые.
- Веб-слой (`app.py`) - приложение Flask, которое связывает модель с HTTP-маршрутами (`/`, `/add`, `/complete/<id>`, `/delete/<id>`). Тестируется через встроенный тестовый клиент Flask без запуска сервера.

4. 15 итераций TDD
Для каждой итерации указано: какой тест был написан (Red), какой код был добавлен (Green) и какой рефакторинг выполнялся.
 
Слой модели (`TaskManager`)
Итерация 1. Пустой список.
Тест: `len(TaskManager()) == 0`. Код: метод `__len__`, возвращающий длину внутреннего списка. Рефакторинг: хранение задач в приватном `self._tasks`.
 
Итерация 2. Добавление увеличивает количество.
Тест: после `add_task(...)` длина равна 1. Код: метод `add_task`, добавляющий элемент в список.
    красный (нет метода add_task)
 
Итерация 3. Заголовок задачи.
Тест: `add_task("Купить хлеб").title == "Купить хлеб"`. Код: создание объекта задачи с полем `title`. Рефакторинг: введён dataclass `Task`.
Итерация 4. Задача по умолчанию не выполнена.
Тест: у новой задачи `done is False`. Код: поле `done=False` по умолчанию.
  
Итерация 5. Уникальные id.
Тест: у двух задач разные, последовательно возрастающие id. Код: счётчик `self._next_id`, увеличивающийся при каждом добавлении.
Итерация 6. Поиск по id.
Тест: `get_task(id)` возвращает задачу, для несуществующего id - `None`. Код: методы `get_task` и `all_tasks`. Рефакторинг: `all_tasks` возвращает копию списка, чтобы внешний код не портил внутреннее состояние.
 
Итерация 7. Пометка выполненной.
Тест: после `complete_task(id)` у задачи `done is True`. Код: метод `complete_task`, переиспользующий `get_task`.
 
Итерация 8. Удаление задачи.
Тест: после `delete_task(id)` длина уменьшается. Код: метод `delete_task`.
Итерация 9. Валидация пустого заголовка.
Тест: `add_task("   ")` вызывает `ValueError`. Код: проверка на пустую строку в начале `add_task`. Рефакторинг: заголовок обрезается через `strip()` перед сохранением.
 
Итерация 10. Подсчёт активных задач.
Тест: `active_count()` возвращает число невыполненных. Код: метод `active_count` с генераторным выражением.
Итерация 11. Очистка выполненных.
Тест: `clear_completed()` удаляет выполненные, оставляя активные. Код: метод `clear_completed`, пересобирающий список.

Веб-слой (Flask)
Итерация 12. Главная страница отвечает.
Тест: `GET /` возвращает статус 200. Код: маршрут `index`, фабрика приложения `create_app()`. Рефакторинг: применён паттерн «фабрика приложения» - у каждого приложения свой `TaskManager`, что изолирует тесты.
 
Итерация 13. Страница показывает задачи.
Тест: после добавления задачи её заголовок присутствует в HTML. Код: HTML-шаблон со списком задач, рендеринг через `render_template_string`.
  
красный (нет маршрута /add, задачи не показываются) и зелёный (13 passed)
Итерация 14. Добавление через POST.
Тест: `POST /add` создаёт задачу и делает редирект (302), задача видна на странице. Код: маршрут `add`, читающий поле формы и вызывающий модель. Рефакторинг: пустой заголовок (ValueError) игнорируется. 

Итерация 15. Выполнение через POST.
Тест: `POST /complete/<id>` помечает задачу выполненной, и на странице она отрисовывается с CSS-классом `done`. Код: маршрут `complete` и условный класс в шаблоне (зачёркивание выполненных задач).
 
добавились маршруты /complete и /delete, оформление и зачёркивание выполненных
